# RFC 3161 验证

浏览器会核对 `.tsr` 原始字节的 SHA-256，并在本地解析 CMS/ASN.1，验证
MessageImprint、TSA 签名、固定 FreeTSA 根证书、证书用途、TSA 身份、关键扩展和
OCSP/CRL 吊销状态。浏览器不使用系统 CA，也不会把 TSR 中附带的证书自动当作信任锚。

RFC 3161 的 `accuracy` 若存在，浏览器会把它转换为保守的毫秒上界并加入
`genTime` 的 round 边界检查；若 receipt 省略该可选字段，浏览器保留 `genTime` 检查并显示
警告。需要严格的离线时间证明时，应使用下面的 CLI，并为省略 accuracy 的 TSA 提供独立的
`--max-accuracy-ms` 上限。

```bash
npm run verify:rfc3161 -- \
  --data summer-test1.json \
  --receipt summer-test1.tsr \
  --ca ../.secrets/tsa-ca.pem \
  --untrusted ../.secrets/tsa-cert.pem \
  --round-time 2026-01-03T00:00:00Z
```

CLI 会解析 RFC 3161 `TSTInfo`，核对 SHA-256 message imprint，通过 OpenSSL 验证 CMS 签名链，
并确认 `genTime + accuracy` 的最晚边界早于 drand round。CLI 只读取本地文件，适合作为浏览器
结果之外的独立交叉检查，不替代 verifier 中固定的 TSA profile。

如果 TSA 回执省略可选的 `accuracy` 字段，必须根据该 TSA 的独立 policy 提供
`--max-accuracy-ms`。没有这个上限时，CLI 会返回 `TSA_ACCURACY_UNAVAILABLE`，不把
仅凭 `genTime` 的结果当成严格时间证明。

只有以上检查全部通过时，命令才返回退出码 `0` 并向标准输出写入 JSON 结果。失败时返回退出码 `1` 和稳定错误码。`--round-time` 必须严格晚于回执中的 `genTime + accuracy` 最晚边界。

每个 TSA 都必须使用为其单独固定的 CA 和中间证书，不得复用其他 TSA 的信任文件。

浏览器只接受 SHA-256、SHA-384 或 SHA-512 的 MessageImprint；SHA-1 会被拒绝。ESSCertID v1 使用 SHA-1 标识签名证书不属于 MessageImprint，两者是不同字段。

当前 FreeTSA 根证书的固定 SHA-256 指纹为 `a6379e7cecc05faa3cbf076013d745e327bbbaa38c0b9af22469d4701d18aabc`。改用其他 TSA 时，必须新增独立信任 profile，包括根证书、固定指纹和允许的 policy OID，不能仅信任 TSR 附带的证书。
